## 2. 关键行为与边界

### F1 `find_in_configs`

- 参数：`keyword`（必填，字面量）、`namespace`、`dataId`、`group`、`maxResults`（1–50，默认 20）、`scanLimit`（v1，1–1000，默认 200）、`caseSensitive`（默认 false）。
- v3：服务端返回匹配元数据后，按 `maxResults` 抓正文生成片段（每配置最多 3 条、每条最多 200 字符）。
- v1：分页列出候选（最多 `scanLimit`），并发 8 抓正文；读取失败的配置进入 `failures`，不拖垮整次搜索。
- 扫描超时标记 `timedOut` 由派发循环与 worker 并发写入，统一经持锁的 `markTimedOut` 更新；超时取消不计入 `failures`。
- v3 的 `configDetail` 必须使用 `*keyword*` 模糊模式（Nacos 3.x 控制台 API 语义）；v1 无原生正文搜索，走扫描回退。
- 输出：`matches`、`scannedConfigs`、`candidateCount`、`failedConfigs`、`failures`、`truncated`、`truncatedReason`、`hint`。
- 无匹配是正常结果（空数组 + hint），不是 `isError`；扫描不完整时显式标记 `truncated`。

### F2 `diff_envs`

- 参数：`namespaces`（2–8，首个为基准，必须互不相同）、`dataId`/`group`、`includeContentDiff`、`maxConfigsPerNamespace`（默认 1000，上限 2000）、`maxDifferences`（默认 100，上限 500）。
- 每个命名空间分页读取元数据，按 `group@@dataId` 与 md5 比较：
  - `only-in-baseline`、`only-in-target`、`different`、`identical`（计数）。
- Nacos 2.4.3 的 blur 搜索响应 `md5` 为 `null`；插件在 md5 缺失时抓取正文并计算 MD5（有 md5 的 v3 不产生额外请求），保证跨命名空间判断正确。
- `includeContentDiff=true` 时只对前 20 条 changed 抓正文生成 diff，避免一次调用过大。
- 单个目标命名空间读取失败会写入 `errors` 并继续；基准命名空间失败则整体报错。
- 结果超过上限时显式 `truncated`。

### F3 `diff_history`

- 参数：`dataId`、`fromHistoryId`（必填）、`toHistoryId`（缺省=当前版本）、`group`、`namespace`、`contextLines`（1–10，默认 3）。
- 输出两侧的 `operator`、`srcIp`、`opType`、`md5`、`createdTime`，以及 `status`（`identical` / `different` / `missing-in-target`）、`added` / `removed` / `diff`。
- 当前配置不存在时返回 `missing-in-target` 而不是工具错误；历史版本不存在时返回可读错误。

### F4 `diagnose`

- 检查项：`protocol`、`health`、`server-state`、`auth-admin`、`credentials`、`namespace-access`、`config-read`。
- v3 `server-state` 读取 `/v3/console/server/state`（匿名平铺 map），解析 `version`、`startup_mode`、`auth_enabled`、`auth_admin_request`、`defaultMaxSize`。
- v1 `server-state` 读取 `/v1/console/server/state`；无鉴权且 `auth_enabled=false` 时不再误报凭据缺失。
- 不可达/错误密码等场景返回 `overall: fail` 的报告（不是工具错误），并给出 `remediation` 与 `suggestions`。
- 全程只读；诊断预算 25 s，单检查 5 s，低于工具总预算 30 s。

## 5. 安全与限制

- 四个工具均为只读；没有新增写路径、凭据输入或请求参数透传。
- 结果继续遵守上游 2 MiB / 工具 6 MiB / 30 s 预算；扫描与漂移显式 `truncated`。
- 错误信息不包含 token、密码、上游正文；正文片段与 `get_config` 同一信任边界。
- v1 正文搜索是客户端扫描，成本随 `scanLimit` 增长；AI 应先收窄 dataId/group。
- `diagnose` 的 `auth-admin` 只提示初始化，不在诊断过程写任何数据。
